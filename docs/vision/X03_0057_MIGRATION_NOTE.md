- **What it adds** (additive only, nothing backfilled, **nothing seeded**), every foreign key `ON DELETE CASCADE`:
  - `EntraideMember` — the **pseudonymous principal**: own random id, account id (unique), chosen pseudonym (3–24, no `@`, no space — CHECK; unique without
    regard to case), status `active` | `suspended` (a suspension needs a time and a reason from the closed list — CHECK), charter version and acceptance time.
  - `EntraideOffer` — member, **category** (closed list: practical help only), **area** (closed list: Strasbourg quartiers and Eurométropole communes — no
    address or position column exists), note ≤ 280 (erased when the offer closes — CHECK), status `open` | `paused` | `closed`.
  - `EntraideRequest` — offer, requester, note ≤ 280 (exists only while `pending` | `accepted` — CHECK), status (`pending`, `accepted`, `declined`,
    `withdrawn`, `ended`); one active request per offer and person (partial unique index).
  - `EntraideContactShare` — the e-mail ONE side chose to show on an accepted request (e-mail shape CHECK; one per side and request).
  - `EntraideReport` — reporter, target, ONE reason (closed list), once per pair, never oneself (CHECK).
  - `EntraideBlock` — blocker, blocked, never oneself (CHECK), once per pair.
  - No score, ranking, distance, message or thread column. The consent proofs (charter, shared e-mails) are `ConsentLog` rows (purposes
    `ENTRAIDE_VOLUNTEER_CHARTER`, `ENTRAIDE_CONTACT_SHARE`).
- **Code without the tables**: `api/_services/entraide.js` asks the catalogue (`entraideSchemaAvailable`): GET says « not available », browse, writes and
  moderation answer 503 `ENTRAIDE_NOT_AVAILABLE`, the export sections are empty (not a failed read).
- **Rollback**: `0057_down.sql` drops the six tables (pseudonyms, offers, requests, shared e-mails, reports and blocks are lost — export first if needed; the
  consent rows stay in `ConsentLog`) and forgets the journal row. Independent of 0053–0056.
