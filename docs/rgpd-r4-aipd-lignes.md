# Release 4 — lignes AIPD proposées (PROJET, à signer par le responsable)

Statut : **projet d'ingénierie du 24/11/2026**, à relire et signer par le responsable du traitement. Aucune relecture par un avocat ou un expert n'est revendiquée. Chaque ligne complète l'AIPD (§ 2.1) ; la capacité correspondante reste fermée tant que sa ligne n'est pas signée (`ADA_CAPABILITIES_OPEN`).

| Ligne | Capacité | Données | Risques principaux | Mesures (code) | Risque résiduel proposé |
|---|---|---|---|---|---|
| **R4-P30 Dossiers partagés (HDS)** | `citizen.shared_dossier` | Texte et documents choisis par la personne (art. 9 possible), structures destinataires, dates, journal sans contenu | Accès d'une structure non voulue ; fuite chez l'hébergeur ; accès conservé après retrait ; consentement non éclairé | Chiffrement de bout en bout (clé du dossier, ECIES vers la clé de chaque structure) ; hébergeur certifié HDS (Scalingo, n° 38436) ne voyant que du chiffré ; consentement explicite par structure à une version de texte approuvée (`HDS_SHARE_CONSENT_VERSION`, absent = partage refusé) ; date de fin ; retrait = re-chiffrement atomique ; journal visible par la personne ; tickets ES256 à usage unique de 60 s ; aucune donnée de santé sur Vercel / Neon (tests canari) | Faible |
| **R4-P31 Pièces jointes chiffrées** | `messaging.attachments` | Fichier PDF / PNG / JPEG (art. 9 possible) d'une conversation de rendez-vous | Lecture par un tiers ; dépôt dans une autre conversation | Chiffrement dans le navigateur pour la personne ET la structure ; ticket lié à la conversation (`obj`) ; Vercel refuse les octets en production ; effacement avec le compte | Faible |
| **R4-P28 Code de secours de Mon Coffre** | `citizen.vault` | Aucune nouvelle donnée en clair : enveloppe chiffrée supplémentaire, empreinte à sens unique | Prise de contrôle par session volée ; perte définitive | Code créé et montré une seule fois dans le navigateur, jamais envoyé ; remplacement de la protection refusé sans preuve de détention de la clé (`authHash`) ; code à usage unique ; texte FALC | Faible |
| **R4-P8 Orientation (contenu chez HDS)** | `pro.referrals`, `partner.referral_adapter` | Clé du dossier enveloppée pour la structure destinataire, note chiffrée ; côté Vercel : codes, états, dates | Transmission sans accord ; texte libre de santé chez Vercel | Proposition en attente : seule la personne l'active ; texte libre refusé par Vercel en production (`FREE_TEXT_IN_HDS`) ; l'événement partenaire ne porte qu'un identifiant (`dossierRef`) | Faible |
| **X02 Témoignages** | `community.testimonials` | Texte, nom choisi, preuves d'accord, signalements | Publication de données de santé / d'un tiers ; harcèlement ; décisions opaques | Relecture humaine avant publication ; accord par texte, retrait = effacement ; modérateur nommé avec MFA ; DSA art. 16, 17, 20, 23 ; délais 24 h / 7 jours affichés dans la file (`NOTICE_SLA_HOURS`) | Faible à modéré (seul modérateur) |
| **X01 Histoires** | `community.stories` | Pseudonyme, texte, preuves | Ré-identification ; mêmes risques que X02 | Pseudonyme séparé du compte ; mêmes mesures que X02 | Faible à modéré |
| **X05 Offres d'emploi** | `community.employment` | Offres d'employeurs vérifiés, moyen de candidature, compte de l'auteur | Discrimination à l'embauche ; collecte de données des candidats | Aucun champ discriminatoire (refus par construction, L1132-1) ; rien n'est enregistré sur les candidats ; relecture avant publication ; signalement public ; effacement du moyen de candidature 30 jours après la fin | Faible |

**Hors périmètre** : X03 (Entraide) reste fermé — AIPD dédiée, responsable de la sécurité et deux modérateurs exigés avant toute ouverture (inchangé).

**Durées proposées par la Release 4 (à approuver)** : dossier partagé effacé 30 jours après sa date de fin (`services/hds/scripts/maintenance.js purge-expired`, exécution à planifier chez Scalingo après approbation). Les durées X01 / X02 / X05 ont été décidées le 22–23/11/2026 ; leurs étapes de purge restent à approuver après lecture du dry-run.
